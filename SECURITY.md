# Security model

This is a custom offline synthetic learning tool, not a production SBOM validator or authentication/vulnerability/license system. Never supply employer/customer/GLPI inventory, credentials or real host/package inventories. The synthetic flag cannot detect such data.

Admitted invented strings/references may still be malformed, deep, large or ambiguous. Byte/tree/count limits, exact built-in API types, duplicate-key/numeric rejection, no coercion/repair and whole common validation precede findings. Ambiguous identifiers never choose first/last. Graph observations require unique resolvable components/edges/roots. All authenticity/completeness assurances remain unknown. Outputs are fixed-schema escaped JSON; diagnostics do not echo exception text or untrusted paths. No model network/process/filesystem/artifact I/O or dynamic plugins.

CLI input/output is ordinary I/O for supplied owned regular fixture files. File checks and exclusive creation are not malicious-filesystem isolation, atomic durability, same-user/admin compromise prevention or time/RSS containment. Relative paths/junctions/links require a trusted owned directory; no hostile path/race guarantee. UTF-8 byte cap bounds reads after a regular-file check; special devices/OS/runtime compromise remain outside claims. No installed dependency or runtime update performed. Standard-library implementation does not prove absence of defects.

Report/file delivery failure can leave partial bytes; check exit status and error state. No automatic fixes or downstream trust decisions. Keep reviewer/manual scrutiny for future expansion. No GitHub-hosted scanner/protection/alerts or publication enabled here.

For a defect, provide a minimal invented bounded fixture and expected/actual outcome to the owner; no public reporting endpoint was established and no automated messages are authorized.
