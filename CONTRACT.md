## Admission and precedence

Exact built-in API containers/values only: dict, list, str, bool, None. Reject subclasses, numeric values, tuples, custom objects and native container cycles without coercion. Shared acyclic containers are allowed. Raw CLI accepts strict UTF-8 JSON without BOM, reads at most 65,537 bytes, rejects >65,536 bytes before decoding; bracket nesting >8 rejected before JSON loading by a string/escape-aware scanner. Duplicate object keys, numbers, NaN/Infinity and malformed JSON INVALID. No raw bad data/exception text printed.

API/decoded tree preflight: depth ≤8 (root container depth 1), ≤4,096 visited values/keys, list/object arity ≤256, individual text ≤256 characters, aggregate text ≤65,536 UTF-8 bytes; reject native cycles, lone surrogates and exotic types. These are admission caps, not a resource containment promise. Reject broad malformed or oversized structures before exact schema checking. Exact-schema root fields: schema/synthetic/components/edges/assertions/roots. All fields required, no extras. synthetic must be literal true. Labels use `[A-Za-z0-9._+-]`, length 1..64; schema labels additionally permit slash so `inventory-lab/2` becomes unsupported after validation. A bounded unknown label is unsupported AFTER every common envelope/record validates. Required component/assertion fields may never be absent; hash is required but null allowed. Wrong type/grammar is invalid even under unknown schema. Numbers/nonfinite tokens invalid, never unsupported.

Maxima: 64 components, 128 edges, 64 assertions, 16 roots; component exact id/name/version/sha256; assertion exact target/name/version/sha256; edge exact source/target. All opaque fields use label grammar. SHA256 null or exactly 64 lowercase hex. Arrays may be empty. Duplicate array declarations admitted for semantic findings, never overwritten. Null/null hash means equal absence of declaration, not artifact equality. All input values are synthetic supplied claims; synthetic=true cannot prove absence of private data.

Order: raw bound → UTF-8/depth/JSON → exact-tree preflight → root/type/count/record-field validation in components, edges, assertions, roots order → schema support → semantic evaluation. Limits stop bounded checking explicitly and give no verdict. Schema/record invalid returns only an admission error, not partial findings/graph. First encountered admission error is reported; no promise of exhaustive malformed-input diagnostics. Within admitted valid input, every record is evaluated before final report.

## Semantic codes and evidence

Findings are grouped, with code, structural path and index-labelled evidence. Codes: duplicate_component_id, unknown_reference, ambiguous_reference (endpoint/target/root paths distinguish them), duplicate_edge, duplicate_root, duplicate_assertion, contradictory_assertions, assertion_mismatch. Duplicate ID finding groups all occurrences (identical or different); every reference to it ambiguous, no first/last selection. Duplicate edge/root/assertion groups all indices of identical declarations. Contradictory assertions: group a target's multiple distinct name/version/hash tuples and indices; no chosen winner. Assertion mismatch: one per uniquely resolved assertion with differing field names, supplied/component values and component index. Unknown/ambiguous assertions get no value-comparison result. No pairwise conflict expansion.

Grouped observations classify repeated name/version labels: `equal_supplied_declarations` if all hash declarations are literally equal (null included), `different_supplied_declarations` otherwise. Preserve occurrence IDs/indices/hash values; never merge records or infer identical artifacts. No hash bytes read, no authenticity proof. Different names with equal hashes get no inferred synonym finding.

Graph is unavailable if ANY duplicate component ID or unknown/ambiguous edge/root reference; reasons are fixed sorted codes. Unresolved assertions do not disable an otherwise well-defined supplied graph. Duplicate edges/roots remain findings, with raw and unique counts; deduplicated only for traversal. Graph nodes include every supplied unique component ID; all supplied edges mean directed depends_on. Iterative SCC traversal produces sorted SCCs and cyclic SCC subset (size>1 or self-edge). Cycles/self-edges produce no inconsistent finding by themselves. Roots empty: reachability not_requested, reachable/not_reached null. Supplied roots: requested, reachable includes the roots, not_reached among supplied nodes only. No completeness inference, no implicit dependency-free/root claim, no all-path/simple-cycle enumeration.

Permutation oracle compares finding semantic groups and graph/declaration observations with indices removed/reprojected; raw indexed reports need not be byte equal. Input is not mutated. Determinism for same input is byte equal under fixed runtime/profile. Exact identity comparison, no folding/normalization/version parsing.

## Report and delivery

Root exact fields: schema=`inventory-report/1`, input_schema (supported/unsupported label or null when admission failed), status, evaluation, consistency, assurances, limits, counts, findings, observations, error. status complete/invalid/unsupported/limit. Evaluation complete iff status complete; consistency consistent/inconsistent then, otherwise null. assurances always completeness/authenticity/vulnerability_absence/license_compliance = unknown. counts present only complete: components, unique_component_ids, edges, unique_edges, assertions, unique_assertions, roots, unique_roots. observations complete: declaration_groups and graph; incomplete null. error incomplete: fixed code/path with no untrusted message; complete null. Limits always documented. Findings ≤1,024; encoded ASCII-safe JSON+LF ≤1 MiB, checked before any delivery. Over-limit report guard fails explicitly without claiming a complete report; guard-seam tests may use reduced constants and must be labelled as seams.

CLI `python -I lab.py INPUT [--output FRESH_FILE]`; source bootstrap is trusted, no install. Stdout complete/admission report by default; fresh output exclusive. API evaluate(value) / evaluate_bytes(bytes) return model report; serialize(report) yields bytes or limit error. Bytes API exact bytes only; wrong API type invalid. Evaluation is pure; transport alone reads supplied owned fixture/writes owned artifact. No host/package/process/network inventory, artifact hashing/execution or actual standards parsing.

Exit 0 complete consistent, 1 complete inconsistent, 2 invalid/usage, 3 unsupported, 4 limit/incomplete, 5 input/output/config/delivery failure. Fully serialize/cap before opening output. Short write, flush, close and ordinary I/O errors exit 5; no successful fallback on stdout after file failure. Bounded escaped error on stderr with no traceback/path/raw exception, error report consistency null. Already-delivered bytes or partial file may remain on I/O failure; no atomic/durable transaction claim. Argparse usage diagnostics replaced with fixed JSON. Filename/terminal content not echoed. No configurable bounds or dynamic plugins.
