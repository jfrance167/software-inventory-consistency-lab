## Problem and success

Invented inventory records can contain ambiguous identifiers, missing relationship endpoints or contradictory supplied assertions while still looking plausible. Build an offline teaching checker that explains those exact inconsistencies and separates them from graph observations and unsupported context. A learner should be able to hand-check every finding against a small fixed input. Reports must state that internal consistency cannot prove completeness, artifact identity/authenticity, vulnerability absence or licensing compliance.

Success: CLI/API produce deterministic bounded reports, all frozen expectations pass under normal and optimized Python, isolated deliberate defects are caught, actual ECC review fixes actionable problems, and README/examples/verification/knowledge note accurately describe limits. No check results are claimed during planning.

## Scope and format

Use standard-library Python, no runtime dependencies. No package installation. Input is a CUSTOM synthetic subset called `inventory-lab/1`, not a CycloneDX/SPDX document, parser or conformance checker. JSON root has exactly `schema`, `synthetic`, `components`, `edges`, `assertions`, `roots`; `schema` is the exact string above and `synthetic` must be literal true. That flag is an analyst assertion, not a privacy or authenticity detector.

Components: exact objects `{id, name, version, sha256}`. All fields are strings; sha256 is null or exactly 64 lowercase hexadecimal characters. ID/name/version use 1–64 ASCII characters `[A-Za-z0-9._+-]`, with no case folding, trimming, Unicode normalization, URL interpretation, version ordering or package-resolution inference. IDs are document-local opaque labels. Name/version are supplied labels, not globally unique artifact identities. Missing required fields are INVALID; only the required hash value permits null.

Edges: exact `{source,target}` strings matching the same ID grammar. All edges mean only supplied directed `depends_on`; typed/scoped/external relationships, nested components/services, PURL/CPE, license data and actual standard formats are excluded. Repeated edge pairs are inconsistent redundant declarations; reverse edges are distinct. Self-edges and directed cycles are permitted and observed.

Assertions: exact `{target,name,version,sha256}`. These explicitly assert all three metadata values about one component ID; null hash asserts a null declared hash, not a wildcard. They are untrusted supplied comparison claims, not oracle truth about bytes. Identical repeated assertions are inconsistent duplicate declarations. Multiple distinct assertions for one target may disagree: report contradictory assertions and mismatches against that uniquely resolved component, without preferring any claim. Unknown or duplicate-ID targets cannot be resolved. Two components with same name/version but different hashes are merely a labelled-identity ambiguity observation, not proof of contradiction; same labels/hash under different IDs is an alias observation, not automatic merging. Same hash with different labels does not prove synonymy or authenticity.

Roots: explicit list of ID strings, may be empty. Duplicate roots are semantic inconsistencies with raw/index evidence, deduplicated only for well-defined traversal. Empty components/edges/assertions/roots is a well-formed empty synthetic inventory with vacuous consistency and unknown completeness. No implicit root inference. No declared dependencies is only zero supplied edges, never proof of dependency-free software.

Unknown version/profile produces unsupported state after bounded structural checking; a known profile with missing/extra fields, wrong types/grammar or duplicate JSON object keys is invalid. Malformed records anywhere invalidate the whole supported input before semantic findings/graph output. Never let an early duplicate, dangling edge or unsupported record hide later malformed data. Over-limit stops bounded validation explicitly and carries no consistency verdict.

## Model rules and observations

Group all component occurrences by ID without overwriting. Every duplicate ID, including identical records, is inconsistent and references to it are ambiguous; do not pick first/last. Track original array indices as evidence locations. Report unknown and ambiguous endpoints independently for source and target, unresolved assertions and roots, duplicate edges/roots/assertions, assertion disagreements and value mismatches. Comparison is literal field equality; hash comparison remains declared-text equality with no artifact read.

Graph analysis is available only if every component ID is unique and every supplied edge/root resolves uniquely. If unavailable, say so with reason; do not drop bad records to create a fictional graph. Duplicate edges can be deduplicated solely for mathematical observations while retaining their finding and reported raw/unique counts. Assertion conflicts do not affect a structurally well-defined graph. Use iterative bounded graph traversal/SCC analysis; sorted SCC membership and reachability result, deterministic self-cycle handling. List cyclic SCCs (size >1 or self-edge) as observations. Roots-empty reachability is explicitly not requested; supplied roots give reachable/not-reached-among-supplied components. Neither means complete nor unnecessary components. Do not enumerate all simple cycles or all paths.

Separate `evaluation` (complete/incomplete), `consistency` (consistent/inconsistent/null), `graph` availability and always-unknown completeness/authenticity. Invalid/unsupported/limit/config/input/output failure cannot emit a consistent result. `complete` means this finite model evaluated all admitted records only. Static findings never authorize external action. Report no risk score/safe verdict or automatic fixes.

## Architecture, bounds and output

Layers: bounded UTF-8 JSON admission → exact schema/type checking → occurrence/index maps → consistency analysis → optional graph observations → deterministic report serializer → CLI transport. Pure `evaluate` receives only admitted ordinary values and validates exact built-in types; public API rejects exotic subclasses/custom iterators, cycles and out-of-bound structures before processing. CLI owns input/output only, not arbitrary target paths. No network/process/package/host collection APIs in model. Use one trusted installed CPython runtime recorded with evidence, no upgrade.

Freeze hard admission maxima: 64 KiB raw input (read cap+1), nesting depth 8 before JSON decoding via string/escape-aware bracket scanner; 64 components, 128 edges, 64 assertions, 16 roots; all labels ≤64 characters, fixed hash width; aggregate report ≤1 MiB UTF-8 and ≤1,024 findings. Fail closed before expensive graph processing; numeric JSON tokens are INVALID and rejected by parse hooks, NaN/Infinity rejected, duplicate keys rejected. Size bounds constrain workload, not hard wall-time/RSS/OS containment. Iterative graph traversal with bounded deterministic sorting; group comparisons aggregate by target/label without quadratic pair listings. Output cap overflow yields explicit incomplete/error, no truncation masquerading as success.

CLI JSON only initially; stdout by default, optional fresh exclusive owned output. Fully validate and serialize/cap report before opening output, check short write and flush/close failure; failed write may leave a partial artifact and must not claim a successful report. No transactional durability/race-proof path containment claim. Restrict examples/evidence to owned project directories; reject source/output alias by exclusive output semantics. Inputs are supplied fictional fixture text; CLI does not attest synthetic flag truth. Escape all diagnostics with JSON encoding; no raw untrusted text, tracebacks/private paths or terminals escapes. No HTML/server/UI scope.

Proposed exit codes: 0 complete+consistent; 1 complete+inconsistent; 2 invalid input; 3 unsupported; 4 limit/incomplete; 5 input/output/config error; argparse usage 2 documented. Failure diagnostics are bounded escaped JSON on stderr, not a fallback successful report. Stable ordering by finding code/input index and sorted graph labels; no timestamps or nondeterministic hashes needed. SHA256 of raw input may identify the analyzed fixture text only, never authenticate it.

## Threat model and exclusions

Untrusted synthetic data can exploit deep JSON, huge arrays/strings, duplicate keys, ambiguous IDs, output amplification or control text; it can also induce false assurance. Mitigate with predecode caps, exact built-in types, whole-input validation, no silent merge/repair, bounded deterministic observations and plain uncertainty. Python/runtime bugs and hostile same-user modifications remain outside model assurances. General-purpose filesystem adversaries/special devices are outside owned-fixture CLI scope; do not claim filesystem sandbox or malware isolation.

No real SBOM, host/package/process inventory, customer/employer/GLPI data, package-manager calls/installation, artifact hashing/loading/execution, vulnerability/CVE APIs, license conclusions, uploads, signature/key/trust checking, remote inference without verified-free controls, TLS/TUF approval workarounds, persistent service/database or live networking. No new repo, push, PR, merge, release, deployment, chat, subagent or scheduler. Preserve parent Git/shared tools/prior lab evidence and limitations.

## Alternatives and decision

Adopting CycloneDX/SPDX libraries provides broad supported schemas and ecosystem semantics, but introduces unnecessary parser/dependency surface and exceeds this synthetic learning purpose. A fork would create ongoing upstream/license maintenance without useful added value. A reachability-only model is smaller but teaches less about ambiguous identity and assertion evidence; integrate only bounded graph observations into the custom model. Choose original standard-library implementation after coordinator approval. Revisit adoption if real format compatibility becomes separately authorized. Dependency count alone is not a security proof.
